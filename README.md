# Suki-match

**半径500m以内の「助けたい」と「助けてほしい」を、15分単位のスキマ時間でつなぐ多世代共助マッチングアプリ。**

少子高齢化を「人口減」ではなく「コミュニティの接続切れ」と捉え、子育て世代の「ちょっとした頼み事」と、シニア・学生の「気軽な社会参加」を結びつけます。

- 例①: 保育園のお迎え後、親が帰宅するまでの15分だけ自宅で見守ってほしい
- 例②: スーパーへ行くついでに、重い荷物を近所の高齢者宅へ届けてほしい

## 主な機能

| 機能 | 内容 |
|---|---|
| 依頼の投稿 | タイトル・内容・所要時間(5〜60分、既定15分)・必要スキル・場所を指定 |
| 半径500mマッチング | ハーバーサイン公式で距離を計算し、500m以内の依頼だけを近い順に表示 |
| スキルマッチ | 依頼の必要スキルと、ユーザーの「できること」が合致する人にだけ通知 |
| リアルタイム通知 | WebSocket(Django Channels)で、近くの新規依頼・受諾・完了・キャンセルを即時トースト通知 |
| 先着1名の受諾 | 同時に複数人が押しても、原子的な更新で1人だけが確定 |
| 完了・キャンセル | 依頼者が完了を確定。ヘルパーのキャンセルは自動で再募集し、近くの人へ再通知 |
| ポイントとランク | 完了で +10pt、高評価(★4以上)のレビュー受領で +2pt。ビギナー → レギュラー(30) → ベテラン(100) → マスター(300) |
| 相互レビュー | 完了後、依頼者・ヘルパーが互いに1〜5で評価(1依頼につき1人1回) |
| 不正検知 | 5件以上マッチして**キャンセル率が50%超**のユーザーは、通知対象から外れ、受諾もできない |

## 技術構成

- Python 3.12 / Django 5.1
- Django Channels + Daphne(ASGI / WebSocket)
- SQLite(開発用)。チャンネルレイヤーはインメモリ

## セットアップ

```bash
git clone <このリポジトリ>
cd suki-match
python -m venv venv
venv\Scripts\activate        # macOS/Linux: source venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py createsuperuser   # 任意(管理画面用)
python manage.py runserver
```

http://127.0.0.1:8000/ を開きます。`runserver` はDaphne経由で起動するため、HTTPとWebSocketの両方が動きます。

> `daphne config.asgi:application` を直接使う場合、静的ファイル(CSS/JS)は配信されません。開発では `runserver` を使ってください。

## 使い方(動作確認の手順)

1. ブラウザを2つ(または通常 + シークレット)開き、それぞれ `/accounts/signup/` でユーザーA・Bを登録
2. 各ユーザーの **マイページ** で「現在地を取得」を押して保存(スキルは「見守り, 買い物」のようにカンマ区切り)。位置情報は手入力でも可
3. Aが **依頼する** から投稿 → 500m以内にいるBの画面に通知トーストが出る
4. Bが「お手伝いする」→ Aに通知 → Aが「完了にする」→ Bにポイント付与
5. 互いにレビューを送信

位置情報のAPI(`navigator.geolocation`)は `localhost` または HTTPS でのみ動作します。

```
core/
  models.py        User, HelpRequest, Match, Review
  services.py      距離計算・スキル判定・通知・不正検知
  consumers.py     WebSocketコンシューマ(通知受信・現在地更新)

```

## 設計メモ・今後の課題

発表資料の構想のうち、現時点で**未実装**のものです。

- **MongoDB**: 資料ではドキュメント型DBを想定していますが、現状は既存構成のSQLite(Django ORM)です。スキルが非定型データになってきた段階で移行を検討します。
- **マイナンバーカード連携による本人確認**: 現状はユーザー名とパスワードのみです。
- **プッシュ通知**: 現状はブラウザを開いている間のWebSocket通知のみです。
- **高度な異常検知**: 現状はキャンセル率のみです。移動履歴などの統計的な外れ値検知は未対応です。
- **本番運用**: `settings.py` の `SECRET_KEY`・`DEBUG`・`ALLOWED_HOSTS` を見直し、チャンネルレイヤーを Redis(`channels-redis`)へ切り替えてください。複数プロセスではインメモリのままだと通知が届きません。
- **プライバシー**: 現在地をDBに保存しています。公開時は保存期間や丸め処理を検討してください。
